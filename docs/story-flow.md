# ToDoList · Story 流（已实现）

> **本文取代** [agile.md](agile.md) 与 [stage-pipeline.md](stage-pipeline.md)。
> 那两版的共同缺陷：都在**增加整理成本**（拖阶段 / 每周开会定迭代）。

---

## 1. 痛点优先级

用户的原话，按重要性排序：

1. **整理时间趋近于零** ← 硬约束
2. 完全掌握一个 story
3. 不能遗漏

三者会冲突：想"掌握"就要记录，想"不遗漏"就要盘点 —— 而记录和盘点都是成本。

**所以唯一的解法是：让记录成为动作的副产品，让盘点成为读一个数字。**

这条原则否掉了两个设计：

| 被否掉 | 否掉的原因 |
| --- | --- |
| 阶段流水线（需求→验证→开发→自测） | 要手动推进；`doing` 用 0 次就是前车之鉴 |
| 周迭代 + 会议 | 要"记得"每周开会定承诺，仪式成本高 |

---

## 2. 只保留一个整理动作

```
committed_at = NULL   → backlog（默认，零成本）
committed_at 有值      → 「现在」（已承诺）
completed_at 有值      → 完成
```

**用户只需要做一个决定：拉进来，或者不拉。**

不需要排序、不需要分桶、不需要拖拽、不需要开会。
新捕获的一切默认落进 backlog —— 捕获永远不需要先想"该放哪"。

### 为什么不是三个桶（现在/接下来/以后）

因为第二、第三个桶会立刻产生一个**额外的分诊动作**，而它们对行为没有影响：
真正影响行为的只有"这周做不做"。所以只保留两态。

## 3. 时间线是自动的，不是维护的

`TaskEvent` 只追加。写入由 API 层在**用户本来就要做的动作**里完成：

| 用户动作 | 自动写入的事件 |
| --- | --- |
| 创建任务 | `created` |
| 拉进「现在」 | `committed` |
| 退回 backlog | `uncommitted` |
| 勾完成 | `completed`（可带一句证据） |
| 取消完成 | `reopened` |
| 批量完成 | 每条一个 `completed` |

于是「完整掌握一个 story」= 打开任务看时间线，**零额外成本**。

```
GET /api/v1/tasks/{id}/events/
→ { count, results: [...], summary: { lead_time_hours, active_hours, has_test_note } }
```

> **反模式警告**：任何状态变化都不要用 `queryset.update()`。
> 它绕过 `events.apply_event()`，时间线会静默丢一条 —— 指标随之失真。
> `bulk` 完成已经改成逐条写事件（略慢，但时间线是真的）。

## 4. 盘点 = 读一个数字

`GET /api/v1/flow/?workspace=<id>` —— 全部派生，无需任何输入：

```jsonc
{
  "now": 0,
  "backlog": 6,
  "done_this_week": 5,
  "wip_limit": 14,          // 近 4 周完成数的中位数 × 1.2（下限 3）
  "wip_exceeded": false,
  "throughput_per_week": [0, 0, 17, 6],
  "oldest_backlog_days": 14,
  "stale_backlog": 5,        // backlog 里超过 14 天没动的条数
  "undated_percent": 85,
  "message": "「现在」是空的。从 backlog 拉几条进来，否则这周没有明确目标。"
}
```

`message` 是**一句话的可执行结论**，不是一堆数字。
用户只需要读这一行，就知道现在该做什么 —— 这就是"盘点"的全部成本。

### 两个刻意的细节

| 细节 | 原因 |
| --- | --- |
| 吞吐用**中位数**不用均值 | 你的数据是批量完成的（某天 13 条、其余 0），均值会被一天拉爆 |
| 周区间用**本地时间的左闭右开区间**，不用 `__week` | `__week=42` 会同时匹配 2025-W42 和 2026-W42 |

## 6. 怎么保证"不遗漏"

不是靠自觉，是靠结构：

| 机制 | 实现 |
| --- | --- |
| 捕获无门槛 | `N` 快捷键全局可用；不填任何字段也能创建 |
| 默认不丢 | 新任务落在 backlog，永不自动归档 |
| 从不由用户删除数据 | 归档而非删除（`is_archived`） |
| 变老会被顶到眼前 | `stale_backlog` 计数 + `message` 主动提示 |
| 完成需要证据（可跳过） | 声称做完是唯一自欺成本高的地方 |

> **"不遗漏"的敌人不是忘记，而是"太多了不敢看"。**
> 所以 flow 条永远只显示 4 个数字 + 1 句话，不会变成一张报表。

## 7. 一句话

> **整理 = 一个动作（拉进现在）。**
> **掌握 = 一条自动时间线。**
> **不遗漏 = 一个会主动说话的计数。**
> 其余全部删掉。
