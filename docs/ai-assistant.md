# ToDoList · AI 任务录入方案

> 目标：把「一段杂乱的想法/会议纪要」变成「工作区里结构化的任务」。
> 约束：用 DeepSeek 的 flash 档模型、API Key 在设置页里配、**尽可能少烧 token**。

---

## 1. 先明确三件事

### 1.1 不做对话

**不做 chat**。没有历史消息、没有多轮、没有"继续"。

理由：多轮对话是 token 消耗的头号来源（每轮都要重发全部历史），
而"把想法变成任务"本质上是**一次无状态的结构化抽取**。
每次请求都是独立的：`文本 + 当前工作区词表 → 任务草稿`。

### 1.2 不让 AI 直接写库

AI 的输出永远是**草稿（draft）**，必须经用户在预览面板确认后才落库。

理由：① 模型会幻觉出不存在的工作区/清单/标签；② 误建脏数据的清理成本远高于确认成本；
③ 复用已有的创建接口，AI 挂了不影响主流程。

### 1.3 Key 不放在浏览器里

设置页输入 Key，但**提交后浏览器再也拿不到它**：

```
浏览器 ──(明文 Key, HTTPS)──► Django ──(Fernet 加密)──► DB
                                │
                                └──(服务端调用)──► api.deepseek.com
```

理由：① 浏览器里的 Key 会被任何 XSS 读走；② 免去 CORS 与浏览器直连的复杂度；
③ 服务端可统一做配额、重试、日志与词表映射。
读取接口只返回 `sk-****abcd` 形式的掩码。

## 2. Token 经济：具体措施

这是本方案的核心。按收益从高到低排列。

| # | 措施 | 省多少 | 说明 |
| --- | --- | --- | --- |
| **T1** | **本地规则解析兜底** | **100%** | `写登录页 @开发 #api !高 明天` 这种带标记的输入用正则直接解析，**完全不走模型**。只有自由文本才发给 AI |
| **T2** | 静态前缀放最前面 | 60–90% | DeepSeek 自动做上下文缓存，命中部分按远低于输入价计费。系统提示词**逐字节固定**，变量（词表、用户文本）全部放后面 |
| **T3** | 输出用 1 字符键 | 30–40% | `{"t":...,"l":...,"p":...}` 而不是 `{"title":...,"list":...}`。输出 token 比输入贵，收益直接 |
| **T4** | 只发**名字**不发 id | 20–30% | 清单/标签只给名字，映射在服务端做。既省 token，又根除"幻觉出 id=999"这类错误 |
| **T5** | 不发全量任务 | 50–95% | **绝不**把工作区已有任务塞进 prompt。只在"查重"场景下用本地字符串相似度预筛出 ≤5 条候选再发 |
| **T6** | 只输出非默认字段 | 15–25% | `p` 是 medium 就不输出；没有截止日就不输出 `d` |
| **T7** | `max_tokens` 给足（**不是省，是保命**） | 见 §2.0 | 900–2500 动态。**上限不是成本** —— 只按实际生成量计费；给太小会「满额计费 + 零产出」 |
| **T8** | 描述截断 | 视情况 | 单条任务描述超过 400 字符就截断，并提示用户 |
| **T9** | 无历史、无 few-shot 堆积 | — | few-shot 示例只放 1 个，且与系统提示词同属静态前缀，吃缓存 |
| **T10** | 配额与可见性 | — | 每次调用记录 token，设置页显示本月累计；超过 `AI_DAILY_TOKEN_BUDGET` 直接拒绝并提示 |

### 2.0 一个代价很高的教训：`max_tokens` 不是省钱的地方

早期把 `max_tokens` 压到 `min(400, 80 + 60 × 预估条数)`，理由是「防止模型跑飞」。
**结果是 100% 失败。** 用真实 API 实测同一条 108 字中文笔记：

| max_tokens | finish_reason | completion_tokens | content |
| --- | --- | --- | --- |
| **320**（旧值） | `length` | 320（**照样全额计费**） | **空字符串** |
| 1500 | `stop` | 283 | 3 条任务 |
| 1750（现在） | `stop` | 1114 | 4 条任务 + 子任务 |

三点结论：

1. **`max_tokens` 是上限，不是花费。** 只按实际生成量计费，给大不会多花钱。
2. **给太小是最坏组合**：调用全额计费，结果一无所有。旧配置每次白烧约 759 token 换来 0 条任务。
3. **输出长度方差极大**（283 → 1114），同一条输入、`temperature=0` 也不保证稳定。
   所以上限必须按**最坏情况**留，而不是按平均值。

顺带修掉两个把「失败」伪装成「没有任务」的地方：

- `finish_reason == length` 现在直接报错并说明被截断，不再说「AI 没有识别出任务」
- 模型返回空内容 / 非法 JSON / 没有任务时，**把原始回复片段带进警告**，否则无从排查

解析也放宽了：裸 JSON 数组、`{"tasks": {...}}` 字典形式，以及
`items` / `data` / `result` / `task_list` 等键名别名都会接受 —— 模型偶尔不按信封格式回。

### 2.1 一次典型请求的实际开销

用户输入：「下周三前和设计对一下登录流程，另外让后端把 refresh 的错误码统一一下，这个算高优先级」

```
[system · 静态 · 可缓存]  ~215 tok
你是待办抽取器……（固定 6 条规则 + 1 个示例 + 输出格式）

[user · 变量]            ~95 tok
清单: 需求梳理|开发|联调
标签: pwa|api|docker
今天: 2026-10-08
---
下周三前和设计对一下登录流程，另外让后端把 refresh 的错误码统一一下，这个算高优先级

[completion]             ~110 tok
{"tasks":[{"t":"对齐登录流程","l":"联调与验收","y":"meeting","d":"2026-10-14"},
{"t":"统一 refresh 接口错误码","l":"开发","p":"high","y":"dev","g":["api"]}]}
```

合计约 **420 token**（其中 215 命中缓存）。2 条任务。
对比"把工作区 24 条任务全发过去"的朴素做法（+约 900 token/次），**省掉约 70%**。

### 2.2 T1：不点 AI，就永远不花钱

**是否使用模型，完全由你决定，没有任何自动判断。**

| 你的动作 | 走什么 | 成本 |
| --- | --- | --- |
| 只在输入框里打字 | 本地标记解析 + 实时预览 | **0** |
| 点「用 AI 分析」 | `POST /ai/parse/ {"mode":"ai"}` → 强制把文本交给模型 | 花 token |
| 直接点「创建 N 条任务」 | 把标记解析出来的结果落库 | **0** |

两条规则，没有例外：

1. **不点 AI → 只按标记识别。**
   没有标记的整段文字就是**一条**任务，不拆分、不启发式、不"贴心处理"。
2. **点 AI → 整段文本原样交给模型**，有标记也照样交。
   标记对模型是有用的上下文（它知道 `#api` 是标签而不是正文），所以不剥离。

`mode=auto` 已移除。猜测用户意图在两个方向上都会猜错：
猜早了白花钱，猜晚了没结果。

> **为什么砍掉自动升级**：早期版本按「含连词 / 超过 2 行 / 超过 40 字」自动升级到模型。
> 实测后果 —— 粘一段没有标记的工作笔记时，因为没配 Key，接口返回 **0 条任务**。
> 决策权交还给你之后，这个失败模式从根上消失。

`^` 前缀保留：它让整行**强制当作标题**，连标记都不解析（用于"我就要这一条，别动它"）。

### 2.3 `shouldEscalate` 只剩提示作用

前后端都仍会算出「这段看起来像散文」（含连词 / >2 行 / >40 字），
但**它不决定任何事**：不触发调用、不改变创建结果。

它唯一的用途是在界面上提示一句
「这段文字没有标记，点左边按钮让 AI 帮你拆分」——
把选择权交给你，而不是替你做主。

## 3. 功能设计

### 3.1 三个入口

| 入口 | 位置 | 行为 | 用 AI？ |
| --- | --- | --- | --- |
| **快速录入** | 每个清单底部的输入框 | 只按标记识别，回车即建 | ❌ |
| **AI 录入** | 工作区页顶部工具栏 | 打开面板 → 打字时实时标记预览 → 需要时点「用 AI 分析」→ 确认草稿 | ✅ 点了才用 |
| **拆解子任务** | 任务行的 `⋯` 菜单 | 拿单条任务标题 + 描述，让 AI 提 3–5 条子任务 | ✅ 点了才用 |

「AI 录入」面板里两条路径的分工写在同一屏上：

```
┌──────────────────────────────────────────────┐
│ 文本                                          │
│ ┌──────────────────────────────────────────┐ │
│ │ 下周2howto text会, real time 和 playback… │ │
│ └──────────────────────────────────────────┘ │
│ [用 AI 分析]  这段文字没有标记，点左边按钮让 AI 帮你拆分 │
│                                              │
│ 将创建 1 条任务（按标记）                       │
└──────────────────────────────────────────────┘
```

未配置 API Key 时，「用 AI 分析」**置灰**并提示去设置 —— 而不是让你点了再吃一个 400。

### 3.2 确认面板（关键交互）

```
┌────────────────────────────────────────────────────────┐
│ AI 分析结果                         2 条 · 420 tok · 缓存 215 │
├────────────────────────────────────────────────────────┤
│ ☑ 对齐登录流程                                          │
│   联调与验收 · 会议 · 10-14            [展开编辑]        │
│ ☑ 统一 refresh 接口错误码                                │
│   开发 · 高 · 开发 · #api               [展开编辑]        │
├────────────────────────────────────────────────────────┤
│ ⚠ 1 条提示：未找到清单「前端」，已归入未分组              │
├────────────────────────────────────────────────────────┤
│                         [取消]  [创建 2 条任务]          │
└────────────────────────────────────────────────────────┘
```

- 默认全选，可逐条取消
- 每条可展开改成普通任务表单（复用 `TaskFormModal` 的字段）
- 服务端只做**校验与归一化**，不替用户做决定
- 确认后一次性调 `POST /api/v1/tasks/bulk-create/`（新增接口，事务内批量创建）

## 4. 数据模型

### 4.1 `assistant.AiCredential`（每用户一条）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `user` | OneToOne → User | |
| `provider` | CharField(20) | 目前仅 `deepseek` |
| `base_url` | URLField | 默认 `https://api.deepseek.com` |
| `model` | CharField(64) | **可配置**，不硬编码，默认 `deepseek-flash` |
| `api_key_encrypted` | BinaryField | Fernet 密文，**永不出库** |
| `is_active` | Boolean | 关掉即停用 AI |
| `last_verified_at` / `last_error` | | 「测试连接」的结果 |

**加密密钥**：独立环境变量 `AI_ENCRYPTION_KEY`。
没有它时回退到由 `DJANGO_SECRET_KEY` 派生（HKDF-SHA256），并在启动日志告警：
**一旦更换 `DJANGO_SECRET_KEY`，已存的 API Key 将无法解密**。
所以生产环境必须显式设置 `AI_ENCRYPTION_KEY`。

### 4.2 `assistant.AiUsageRecord`（审计 + 配额）

| 字段 | 说明 |
| --- | --- |
| `user` / `kind` | `parse` / `split` / `test` |
| `model` / `ok` / `error` | |
| `prompt_tokens` / `completion_tokens` / `cached_tokens` | 直接用 API 返回的 `usage` |
| `latency_ms` | |
| `source` | `local` / `ai` —— 便于统计本地解析省下了多少请求 |

### 4.3 为什么不建 `AiDraft` 表

草稿存活时间只有"用户看一眼"的几秒。放服务端要处理过期、权限、并发删除，
而放前端 state 就是零成本。**刷新丢失是可接受的**（重发一次即可）。

## 5. API 契约（新增）

前缀 `/api/v1/ai/`，全部需登录。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/ai/credential/` | 返回 `{configured, provider, model, base_url, key_mask, is_active, last_verified_at, last_error, models_available}`；**永不返回明文** |
| `PUT` | `/ai/credential/` | `{api_key?, provider?, model?, base_url?, is_active?}`；`api_key` 为空表示不改 |
| `DELETE` | `/ai/credential/` | 删除凭据 |
| `POST` | `/ai/credential/test/` | 用 `max_tokens=1` 探测 Key 是否有效，返回 `{ok, model, latency_ms, error?}` |
| `POST` | `/ai/parse/` | 见下 |
| `POST` | `/ai/split/` | `{task_id}` → `{subtasks:[{t}], usage}` |
| `GET` | `/ai/usage/` | `?days=30` → 汇总 + 最近 20 条 |

### `POST /ai/parse/`

```jsonc
// 请求
{
  "workspace": 1,
  "text": "下周三前和设计对一下登录流程，另外让后端把 refresh 的错误码统一一下",
  "mode": "auto",          // auto | local | ai   —— 默认 auto（先本地后 AI）
  "default_list": 7,        // 可选，本地解析不到清单时的兜底
  "default_type": "dev"     // 可选
}

// 200
{
  "source": "ai",                       // local | ai
  "tasks": [
    { "t": "对齐登录流程", "l": 9, "l_name": "联调与验收",
      "p": "medium", "y": "meeting", "d": "2026-10-14", "g": [], "g_names": [],
      "s": ["确认参会人", "定会议时间"] }
  ],
  "warnings": [ { "code": "list_not_found", "message": "未找到清单「前端」，已归入未分组", "value": "前端" } ],
  "usage": { "prompt_tokens": 95, "completion_tokens": 110, "cached_tokens": 215, "total_tokens": 205 },
  "latency_ms": 1840
}

// 400 未配置
{ "detail": "尚未配置 AI，请先在设置页填入 API Key。", "errors": { "credential": ["未配置"] } }
// 429 超配额
{ "detail": "今日 AI 配额已用尽（12000/12000 token），明天再试或调高上限。", "errors": {} }
// 502 上游失败
{ "detail": "DeepSeek 调用失败：401 Invalid API key", "errors": {} }
```

### `POST /tasks/bulk-create/`（新增，非 AI 专用）

```jsonc
{ "tasks": [ { "workspace":1, "task_list":9, "title":"…", "priority":"high", … } ] }
// 201 { "created": 2, "tasks": [ … ] }
```

事务内批量创建；任一条校验失败则整体回滚并返回第几条第几个字段出错。

## 6. 提示词设计

**系统提示词逐字节固定**（吃缓存），变量一律放 user 消息。

```
你是待办抽取器。把用户的一段话拆成任务，只输出 JSON。

格式：{"tasks":[{"t":"标题","l":"清单名","p":"low|medium|high|urgent","y":"dev|meeting|communication|design|research|other","d":"YYYY-MM-DD","g":["标签名"],"s":["子任务标题"]}]}

规则：
1 只输出 JSON，不要解释、不要 markdown 代码块。
2 t 必填，简洁动宾短语，不超过 30 字。
3 没有依据的字段一律省略，不要猜。
4 l 只能取给定清单名之一；g 只能取给定标签名之一。
5 一句话包含多件事就拆成多条，最多 8 条。
6 s 仅在明显需要拆解时给出，最多 5 条，每条不超过 20 字。
7 d 只能是 YYYY-MM-DD，相对日期以「今天」为基准换算。
```

```
清单: 需求梳理|开发|联调与验收
标签: api|docker|pwa
今天: 2026-10-08
---
<用户原文>
```

调用参数：

| 参数 | 值 | 理由 |
| --- | --- | --- |
| `temperature` | `0` | 抽取任务要确定性，不要创意 |
| `response_format` | `{"type":"json_object"}` | 免去解析 markdown 代码块，省 completion token |
| `max_tokens` | 900–2500，动态，见 §2.0 | 上限不是成本；给太小会满额计费却零产出 |
| `stream` | `false` | 草稿要整体校验，流式没意义 |
| `timeout` | 30s | 超时直接失败并提示重试 |

**容错**：模型仍可能返回带 `\`\`\`json` 围栏的内容，解析器先剥围栏再 `json.loads`；
解析失败时按 `{"tasks": []}` 处理并记 `last_error`，绝不 500。

## 7. 后端结构

```
backend/apps/assistant/
├── models.py         AiCredential / AiUsageRecord
├── crypto.py         Fernet 加解密 + 密钥派生
├── prompts.py        固定的系统提示词常量
├── deepseek.py       客户端（httpx，超时/重试/usage 解析）
├── local_parser.py   本地规则解析（T1）
├── services.py       词表构建 / 输出归一化 / 配额校验 / 落库记录
├── serializers.py
├── views.py
├── urls.py
├── admin.py
└── tests/            全部用 mock，不打真实网络
```

新增依赖：`httpx`（HTTP 客户端）、`cryptography`（Fernet 加密）。

**归一层要做的脏活**（把不可信的模型输出变成可信的领域对象）：

| 输入 | 处理 |
| --- | --- |
| `l` = "开发" | 查词表 → 映射为真实 list id；查不到 → warning + 归入未分组 |
| `g` = ["api"] | 查词表；查不到 → `get_or_create` 创建标签 |
| `p` = "High" | 大小写归一；非法值 → 丢弃，用默认 |
| `d` = "2026-10-14T00:00:00Z" | 只取日期部分；非法 → 丢弃 + warning |
| `t` 为空或超 200 字 | 截断/丢弃 + warning |
| 返回 30 条 | 截断到 8 条 + warning |
| `tasks` 不是数组 | 视为空 + 记错误 |

## 9. 安全与成本防线

| 风险 | 措施 |
| --- | --- |
| Key 泄漏 | Fernet 加密存储；接口只回掩码；日志脱敏（只记前 6 位） |
| Key 被盗刷 | 每日 token 配额 `AI_DAILY_TOKEN_BUDGET`（默认 50k/用户） |
| SSRF | `base_url` 只允许 `https://`，拒绝私网段与 `localhost`（管理员白名单可放开） |
| 提示词注入 | 用户文本只作为 `user` 内容，且用 `---` 分隔；系统提示词不可被覆盖；输出仍然过归一层 |
| 上游抖动 | 10s 连接超时 / 30s 读超时；失败不重试（避免重复计费），直接提示用户 |
| 费用黑盒 | 每次调用落 `AiUsageRecord`，设置页可见 |

> **不重试**是刻意的：DeepSeek 的请求可能已经计费，盲目重试会双倍扣费。
> 交给用户手动点「重试」更诚实。

## 10. 实施顺序

| 阶段 | 内容 | 可独立交付 |
| --- | --- | --- |
| **P1** | 本地解析器（前后端）+ `bulk-create` 接口 | ✅ 零成本，先解决 70% 录入 |
| **P2** | 凭据管理（加密、设置页、测试连接） | ✅ |
| **P3** | `POST /ai/parse/` + 确认面板 | ✅ |
| **P4** | 子任务拆解、用量统计、配额 | ✅ |
| **P5** | 会议纪要长文本分块、查重合并建议 | 后续 |

P1 单独就有价值，且完全不依赖 API Key。

## 11. 明确不做

- ❌ 对话式聊天助手（token 黑洞，且与"随手记录"的定位冲突）
- ❌ 自动后台分析（用户没点就不该花钱）
- ❌ AI 直接改/删已有任务（只创建，且必须确认）
- ❌ 把工作区全量数据塞进 prompt
- ❌ 向量检索/RAG（个人工作区规模下，本地字符串匹配足够且免费）
